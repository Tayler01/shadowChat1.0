# ShadowPin discussion read position and attachments

The September 30 implementation uses `shadow_pin_comment_read_cursors` for an owner-private per-image `(created_at, id)` cursor. It does not treat opening the comments sheet as reading all discussion notifications.

- An explicit comment link loads a contiguous window around that visible comment. An unavailable target shows a recovery action without acknowledging unrelated rows.
- Returning during the same session restores the visible comment and its pixel offset, unless an explicit link takes priority.
- A fresh open with a saved cursor fetches the actual first unread comment before choosing a window, even when unread history exceeds one page. A cursor lookup error remains retryable. A first visit with no cursor deliberately opens latest; previous historical comments are not presented as an unread backlog.
- Windows contain 40 comments initially, with older/newer keyset pages and a 200-row retained cap. The chronological display preserves reply indentation without moving new replies ahead of older unread comments.
- The shared scroll controller owns exact targets, bottom following, visible ID/offset anchors, layout changes and settled read observations. Reconnect reconciles the loaded window. Incoming comments while reading history show a pending indicator; own sends reveal the submitted comment.
- `mark_shadow_pin_comments_read` accepts observed IDs, derives timestamps from caller-visible rows, advances only through contiguous observed unread comments and clears only exact observed comment/reply notification events. Cursors cannot change owner/image or rewind. Closing a sheet is not a blanket discussion read.

Attachments stay local until Send. Clipboard files, drops and the file picker use shared staged intake, with at most three files per batch and 50 MiB per file. Text is sent as a comment; each staged file is sent as its own comment with its filename, retaining reply context. Draft text remains editable while sending. Failed sends retain the upload for retry, and a stable upload UUID identifies the comment so an uncertain insert can be reconciled. Definitively unsent canceled uploads retain failed cleanup paths in an account-scoped device queue and retry on the next same-account mount or online event; ambiguous sends never enter that queue.

Comment Edit preserves the existing column-level body update grant and author/visibility policies. The client preserves attachment, author and reaction presentation when the edited body returns.

`shadow-pin-comments` is a private Storage bucket. Paths contain author/image/unique UUID, comment inserts validate provenance, readers inherit comment/image visibility and reciprocal blocking, and URLs expire after ten minutes. The Storage delete policy checks all references through a narrowly authorized private helper, including comments hidden from caller RLS. A trigger-derived object foreign key also prevents a concurrent cleanup from removing a newly referenced object. Canceled completed uploads and confirmed comment deletion use Storage removal; network failures can retain a private object and must not be reported as verified cleanup. A failed cleanup after confirmed comment deletion remains available as a persisted retry action.
